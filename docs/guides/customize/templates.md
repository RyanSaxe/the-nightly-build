# Templates

Create a template only when the proof should enforce a recurring structure.
Voice, subject, and most genres belong in series prompts; a template is the
stronger tool for invariant sections, citation geometry, chrome, or required
furniture.

A template is enforced law. Every fixed section, band, and citation rule in
`press/templates/<id>/` becomes something the proof blocks on for every future
article using the template. The decision that deserves your attention is which
structure is invariant and which stays open to the subject. The
[Template reference](../../reference/templates.md) defines the package
contract and names the shipped templates.

Your assistant runs the design process. Expect it to draft the contract, fill
the skeleton cheaply for materially different subjects, and open the rendered
results in your browser so you react to real pages instead of schemas. It
should ask you to settle what is enforced before the manifest hardens, and
test the proposal against article ideas that should fit and one that should
not. A fill you approve becomes the package's sample.

A `press/templates/<id>` package shadows a shipped template with the same ID
wholesale. Prefer a new ID unless replacement is deliberate.
