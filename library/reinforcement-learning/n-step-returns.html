Reinforcement Learning

Four-step TD learns a 19-state random walk faster than TD(0) or Monte Carlo

Over the first 10 episodes, with each method at its best step size, TD(0) passes the outcome back one estimate at a time and noise in Monte Carlo's returns holds its best step size to 0.022.

20 min read2026-11-10

Why this matters

Under TD(0), an episode's outcome reaches the earlier states only through the estimates in between, about one state per pass over an episode. Monte Carlo moves every visited state toward the outcome at once. It has to wait for the episode to end, though, and its target carries the randomness of every move left.

A target between the two adds the rewards of the next n moves and then the estimate of the state they reach. The method is called n-step TD. With n = 1 it is TD(0), and with n longer than the episode it is Monte Carlo. After working one episode by hand under three values of n, you will code an update that waits n moves for its target and see on a 19-state random walk why a middle n learns fastest at first.

How far the outcome of one episode reaches

This lesson's random walk has 19 states in a row. Each move goes one state left or right with probability ½. Moving left from state 1 ends the episode with reward −1, moving right from state 19 ends it with +1, and every other move pays 0. There is no discount, so the return from any time is the outcome. Sutton and Barto use this walk to compare n-step methods.1

Only the ends pay, so a state's value is the average of its two neighbours' values, with a move off an end worth that end's outcome. That puts the values on a straight line from −1 just past state 1 to +1 just past state 19, so state s is worth s/10 − 1.

Fig. 1 follows one six-move episode with every estimate at 0. The agent goes from state 16 to 17, 18, 17, 18 and 19, then off the right end for +1. Each row is a time t. Each column on the right is a rule for the target that V(St), the estimate of the state at time t, moves toward.

TD(0)'s target, in the n = 1 column, is the reward plus the estimate one move later. Five of its six targets read a 0, so only V(19) changes. Monte Carlo's target, in the n = 6 column, is the return, +1 at every time, so every visited state moves toward +1.

The n = 3 target adds the next three rewards and then the estimate three moves later. From time 3 on, the episode ends within three moves, and the target is the +1 itself. Three moves after time 0 the agent is in state 17, one state from where it began, because n counts moves and the walk doubled back.

With a step size of 0.5, n = 3's first three targets read estimates that are still 0 and change nothing, and its last three move V(17), V(18) and V(19) to 0.5. n = 6 also moves V(16) to 0.5, and its targets are all +1, so V(17) and V(18) move twice, to 0.75.

The general target is the n-step return.1 Vk is the table of estimates after the update made at time k.

The update moves V(St) toward that target by a fraction α of the gap.

With n = 1 the target is TD(0)'s, Rt+1 + γV(St+1). With n at least the number of moves left, it is the return, and the update is constant-step Monte Carlo on every visit. Watkins introduced this target in his 1989 thesis as the "corrected n-step truncated return".2

The n-step error is the first n TD errors

Building the n-step return one move at a time shows where it sits between TD(0) and Monte Carlo. Hold the estimates fixed, so V needs no time subscript. Splitting off the first reward leaves an (n − 1)-step return that starts at t + 1 and stops at the same time, t + n. A return that stops where it starts is defined as the estimate there.

Subtract V(St) from both sides, then add and subtract γV(St+1).

Each δk is a TD error. Monte Carlo's correction Gt − V(St) is the discounted sum of every TD error to the end of the episode, and TD(0)'s correction is the first term. n-step TD's correction is the first n terms. Because n-step TD changes the estimates during an episode, for it the identity is only approximate.

In Fig. 1 every TD error is 0 except the last, δ5 = +1. The n-step error at time t is then 1 when t + n ≥ 6 and 0 otherwise, which is the n = 3 column.

The target for time t is complete at time t + n

No algorithm can use Gt:t+n before time t + n, when Rt+n and St+n arrive.1 So the move from time t to t + 1 completes the target for time τ = t + 1 − n, and no estimate changes during the first n − 1 moves. When the episode ends, the last n times are still waiting. Their targets reach the end, so each is a return, and they are applied after the final move.1

In nstep.py, walk yields one move at a time, so nstep_td sees each reward only when its move happens. With no discount, a running sum C of the rewards turns each target's sum into one subtraction.

The output matches the hand-worked estimates for Fig. 1's episode.

n = 4 has the lowest error at its own best step size

To see which n learns fastest, sweep.py repeats the experiment behind Sutton and Barto's Figure 7.2. As in Sutton's code for that figure, every episode starts at state 10, the middle, every estimate starts at 0, and every setting plays the same walks.3 The starting estimates put the root-mean-square (RMS) error over the 19 states at about 0.55. The script averages the RMS error after each of the first 10 episodes over 100 runs, for 26 step sizes and ten values of n.1 The largest n is ∞, a target that never bootstraps, which is Monte Carlo.

At its own best step size, n = 4 has the lowest error, 0.26 at α = 0.37, against 0.34 for TD(0) and 0.49 for Monte Carlo. New seeds for three more sets of 100 runs keep n = 4 lowest by similar margins. n = 3 and n = 5, which the sweep skips, tie with it, so the best n is a range around 4. Sutton and Barto's Figure 7.2 has the same shape, with n = 4 lowest. They report that an intermediate n worked best and give no reason.1

The best step size falls as n grows, so which n does best changes with α. At α = 1, TD(0) has the lowest error, and at α = 0.05, n = 32 does.

Small n carries the outcome back slowly and large n needs a small step

Fig. 3 shows what three of the methods learned by episode 10, each at its best step size.

TD(0)'s estimates are close to the true values near the ends and fall short further in. The outcome reaches a state only through the estimates between it and the end. So the further a state is from the nearer end, the less of its true value the mean has reached: about half at state 6. At state 10 the true value is the starting 0, so there TD(0) is already right.

Monte Carlo's estimates spread more widely than n = 4's at all but one state, at a far smaller step size, and their mean is flattened toward 0. A walk from the middle passes the middle states many times, and in one episode every visit moves them toward the same outcome, +1 or −1, though their true values are near 0. Those moves add up like one large step, so only a small step keeps an estimate near the average over many episodes. At the best step, 0.022, the rarely visited states near the ends have moved only a fifth of the way.

n = 4's estimates stay close to the true values at every state. Its targets take the outcome from up to four moves away, and a target that bootstraps reads an estimate four moves on, which varies far less than a return of +1 or −1.

sweep.py --expected checks the noise half of this explanation. It replaces each target with its expected value, computed from the current estimates and the walk's move probabilities, which the agent does not know. The same states update in the same order. Monte Carlo's expected target is the true value itself, so this run was bound to rank Monte Carlo first, and that ranking is not a test. The run measures what the noise cost. Without it, Monte Carlo's error falls from 0.49 to 0.06, the error of states no walk has reached yet, and TD(0)'s only from 0.34 to 0.28. A small step averages many noisy targets, so with no noise α = 1 is best for every n. TD(0)'s remaining error comes from how slowly the outcome moves back through the estimates.

The same explanation predicts that TD(0) wins when the outcome has to be carried back only a few states, or when the estimates already carry it. TD(0) is best on a 5-state walk (--size 5) and on the 19-state walk over episodes 91 to 100 (--episodes 100 --first 91). The best n depends on the step size, the length of the chain and how long training has run.

sweep.py, complete, and its four outputs

sweep.py imports nstep.py from the same folder. Each run takes under 10 seconds on the machine used here, except the run over 100 episodes, which takes about 40.

Problems

1. An episode starts in state 18, moves to 19, 18 and 19, then steps off the right end for +1. The estimates are V(18) = 0.5 and V(19) = 0.7, with n = 2 and α = 0.5. Give each time's target, when it is complete, and the two estimates after the episode. Then check that the first target's error equals δ0 + δ1.

Answer

The target for time 0 is complete at time 2 and is V(S2) = V(18) = 0.5, so V(18) stays 0.5. The target for time 1 is complete at time 3 and is V(S3) = V(19) = 0.7, so V(19) stays 0.7. The episode ends at T = 4, so the targets for times 2 and 3 are the return, +1, applied after the last move. V(18) becomes 0.75 and V(19) becomes 0.85. For the check, δ0 = 0.7 − 0.5 = 0.2 and δ1 = 0.5 − 0.7 = −0.2, which sum to 0, the first target's error.

2. Every estimate starts at its true value, s/10 − 1, instead of 0. Which n gives the lowest error over the first 10 episodes, and why?

Answer

TD(0), at every step size. The estimates already carry the outcome, so only noise in the targets moves them away from the true values. TD(0)'s target is a neighbour's true value, 0.1 from the current state's. A longer target reads a state up to n states away, and the return is +1 or −1.

The takeaway

n-step TD moves V(St) toward the rewards of the next n moves plus the estimate of the state n moves later, once that state is reached. With n = 1 it is TD(0), and with n past the episode's end it is every-visit Monte Carlo with a constant step size. With fixed estimates, its correction is the first n of the TD errors that sum to Monte Carlo's correction. On the 19-state walk over the first 10 episodes, n = 4 had the lowest error at its best step size. Under TD(0) the outcome moved back slowly, and Monte Carlo's noisy returns forced a small step. Removing the noise cut Monte Carlo's error far more than TD(0)'s.
