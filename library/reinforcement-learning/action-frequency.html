Reinforcement Learning

Deciding ten times as often leaves Q-learning a tenth of the gap between two pushes

Tabular Q-learning picks the right push in 71% of a docking cart's safe start cells at 0.01 s steps, and in 94% when Gymnasium's RepeatAction holds each push for ten steps, mainly because the gap widens tenfold.

22 min read2026-11-15

Why this matters

How often an agent acts is a choice the environment's designer makes. In a simulated system it is the length dt of each step. A shorter step gives finer control, and it also makes the actions harder to tell apart. Holding an action for dt seconds moves the system a distance proportional to dt. So the action values of two actions in one state differ by an amount proportional to dt, called the action gap. Q-learning has to see that gap through estimates whose error doesn't shrink with dt. Holding each action for several steps, called action repeat or frame skip, widens it again. Working through a cart pushed toward a dock, you predict the gap at any step length from the dynamics, set the discount per step from a horizon in seconds, and test which of RepeatAction's effects helps Q-learning.

A wrong first push costs a tenth as much when it lasts a tenth as long

This lesson rebuilds Dock, the cart from the lesson on observation scale, so that the length dt of a step can change (Fig. 1). The track now runs 1 m, from a back end at x = 0 to the dock at x = 1. The state is the cart's position x and its speed v. Each step the agent pushes left or right, which accelerates the cart at 1 m/s² for dt seconds. Dock computes the motion within a step exactly, so every dt runs the same physics. Each step pays minus its length in seconds, and docking at any speed ends the episode. Rolling off the back end ends it too and pays −2 more. Each step is discounted by e−dt/τ with τ = 1 s, a horizon of 1 s at every dt.

Pushing right is the best move in every state. It docks the cart soonest, and a cart that will roll off anyway rolls off later, when the −2 is discounted more.

Put the cart at rest at x = 0.5 and compare two first moves. Pushing right throughout docks it at 1.000 s. A left push for the first step leaves the cart 2·dt m/s slower than a right push would, so it docks 0.21 s later when dt = 0.1 and 0.02 s later when dt = 0.01.

The return falls with the delay. At dt = 0.1 the two first moves return −0.664 and −0.737, which are 0.073 apart. At dt = 0.01 they return −0.635 and −0.643, only 0.0074 apart. The state's value barely moved, while the difference between the moves fell tenfold. To choose the better push at dt = 0.01, an agent has to estimate two returns near −0.64 well enough to separate values 0.0074 apart.

Every action's value differs from the state's value by O(dt)

The same tenfold drop happens in any system whose state moves continuously and whose value changes smoothly. Tallec, Blier and Ollivier prove it as their Theorem 2, an argument they credit to Baird.1

Write the system as ds/dt = f(s, a) with a reward rate r(s, a) per second, and fix a deterministic policy π with values V and Q. One step holds the action a for dt. It moves the state to s′ = s + f(s, a)·dt + o(dt), pays r(s, a)·dt, and discounts what follows by γ = e−dt/τ.1

The discount comes from τ, a horizon in seconds. A reward of 1 per second forever returns dt/(1 − e−dt/τ), which tends to τ as dt shrinks. The horizon in steps, 1/(1 − γ), grows as τ/dt. Doya's formulation of continuous-time reinforcement learning uses the same discount, with τ as its time constant.2 A discount held fixed per step would shrink the horizon in seconds along with dt.

Substitute the second and third lines into the first and keep the terms of first order in dt.

The bracket stays bounded as dt shrinks, so Q(s, a) − V(s) = O(dt) for every action, and in the limit the first action stops mattering. Tallec et al. conclude that there is no continuous-time Q-learning.1 With two actions, the difference between their values in one state is the action gap.3 Subtracting the line for one action from the line for the other cancels V/τ.

In Dock, s = (x, v) and f(s, a) = (v, a), with a = ±u and u = 1 m/s². Both pushes pay −1 per second, so only the speed component differs, by 2u.

Under the policy that always pushes right, a cart that docks does so after T = (w − v)/u seconds, where w = √(v² + 2u(1 − x)) is its speed on arrival, and V = −τ(1 − e−T/τ). At (0.5, 0), T = 1 s and ∂V/∂v = e−1 ≈ 0.37 per m/s, so the gap is 0.736·dt. That policy is optimal, so its gap is the one Q-learning has to learn.

gap.py measures the gap. Dock is deterministic, so one rollout per first move gives each action value exactly. Run on its own, dock.py passes Gymnasium's environment checker.

dock.py and gap.py, complete

At (0.5, 0) the gap divided by the decision's length h stays between 0.731 and 0.736 from dt = 0.1 down to 0.0001, against the derived 0.736 (Fig. 2).

The expansion needs V to be smooth, and Dock's V jumps along one curve. A cart moving left with v² > 2ux rolls off even if it pushes right, and the edge of that region is the brink. The second state in gap.py lies so close to it that pushing right stops the cart 0.5 mm from the back end. Down to dt = 0.001, one left push carries it across, so its gap stays between 0.68 and 0.85. At dt = 0.0001 the push is too short, and the gap falls onto its derived line. At any dt, the states whose stopping point lies within about 2|v|·dt of the back end keep a gap like this, and that band narrows with dt. Tallec et al. meet the same kind of jump in pendulum swing-up and say their analysis holds only almost everywhere.1

At dt = 0.01, Q-learning's estimates vary more than the gap

Now let Q-learning find the gap. qcells.py runs the Q-learning update on a table with one row per cell of 0.1 m by 0.2 m/s. Position and speed together are Markov, as the frame-stacking lesson required of an observation, but a cell holds many states, so each entry averages over the states behind it. The target still bootstraps when Dock's 20 s limit truncates an episode.

Each decision of h seconds is discounted by e−h/τ, so the horizon stays at 1 s. The step size is a constant 0.3 in every run, since one that shrank with each entry's update count would shrink sooner when decisions come more often.

runs.py trains 10 agents, seeds 0 to 9, each for 2,000 s of simulated time. It reports the share of the 86 safe start cells, those with |v| ≤ 1 and no state past the brink, whose greedy move is right. It also checks whether each greedy cart docks from 12 fixed starts, and how much one estimate varies across runs. It needs dock.py and qcells.py in its folder, and each call took under 30 seconds here.

runs.py, complete

At dt = 0.01 the agents push right in 71% of the safe cells, and only 3 of 10 dock from every start. Across runs a typical estimate varies by about 0.05, six times the 0.0074 gap at (0.5, 0). Tallec et al. place Q-learning's failure here: once an estimate's error is much larger than O(dt), the error decides which action ranks first.1

RepeatAction holds each push for ten steps and widens the gap tenfold

Action repeat holds each chosen action for k steps, so a decision lasts h = k·dt. Gymnasium 1.3.0 added it as the wrapper RepeatAction. The wrapper steps the environment k times, adds the rewards without discounting, returns the last observation, and stops early if the episode ends.4 Ten Dock steps of 0.01 s pay the same −0.1 as one step of 0.1 s. So the last row of gap.py's gap table, RepeatAction(Dock(0.01), 10), matches the dt = 0.1 row, and the gap at (0.5, 0) is 0.073 again.

uv run runs.py --repeat 10 wraps Dock(0.01) the same way, with the same physics and the same budget of 2,000 s.

The agents now push right in 94% of the safe cells, and all 10 dock from every start (Fig. 3). A typical estimate varies by 0.013, under a fifth of the 0.073 gap. With a decision every 0.01 s the spread was 0.047, so the shorter decision left the estimates no more precise and the gap ten times smaller.

Most of repeat's gain in Dock comes from the wider gap

Repeat changes two other things. A random move now lasts 0.1 s, and Tallec et al. prove that as dt shrinks, ε-greedy's random moves average out, so the agent follows one deterministic path and explores little.1 The 1 s horizon also spans 10 decisions instead of 100. Kalyanakrishnan et al. bound what errors in the estimates cost by a term that falls as the horizon in decisions shortens.5 Two flags each give the agent one of these effects while every greedy move still lasts 0.01 s. --explore-repeat 10 holds only the random moves for 10 steps, a fixed-length form of Dabney, Ostrovski and Barreto's εz-greedy, which holds each random move for a random duration.6 --tau 0.1 gives each 0.01 s step the discount of a 0.1 s decision without repeating anything.

Holding the random moves raises the share to 0.79, but only 2 runs dock from every start. The shorter discount leaves the share at 0.70. That arm can't fully separate the horizon from the gap, because a 0.1 s horizon also flattens V far from the dock and so, by the derivation, shrinks the gap further. Neither arm comes near repeat's 0.94 or its 10 runs that dock from every start, so in Dock most of repeat's gain comes from the wider gap.

A held push can't respond until its decision ends, so a long repeat costs control. Pushing right is always best in Dock, so holding it costs nothing here, and problem 1 asks what it costs when the best move changes.

Problems

1. Suppose the dock accepts the cart only below 0.5 m/s, and a faster arrival pays −2 like the back end. Is pushing right still best everywhere? Where does V gain a new jump, and what does holding each push for 0.5 s cost there?

Answer

No. A fast cart near the dock has to push left to brake. V jumps along the curve v² = 0.25 + 2u(1 − x), beyond which even braking all the way arrives faster than 0.5 m/s. The curve meets the dock at v = 0.5, so this jump sits next to the goal. The gap there stays finite as dt shrinks, as at the brink. The fastest safe approach starts braking just before the curve. With a decision every 0.5 s, braking can start only at a decision, so the cart must start up to 0.5 s early and docks later.

2. DQN repeats each action for 4 frames of a 60 Hz emulator, which its authors chose to save computation. It discounts by γ = 0.99 per decision.7 Its repeat of 4 is a separate setting from its stack of 4 frames. What horizon τ in seconds does that give, with the discount set per step as in this lesson? What discount per frame keeps that τ if the agent decides on every frame?

Answer

A decision lasts h = 4/60 s, and γ = e−h/τ gives τ = −h/ln 0.99 ≈ 6.6 s, which is 100 decisions. Deciding every frame cuts h to a quarter, so the discount per frame is 0.991/4 ≈ 0.9975: four frames together must discount by 0.99.

The takeaway

Deciding more often shrinks the differences the agent has to detect. An action held for h seconds changes a smooth system's state, and so its value, by O(h). Two actions' values in one state therefore differ by O(h), while the error in a learned estimate doesn't shrink with h. In Dock at h = 0.01 s, Q-learning's estimates varied by six times the gap, and its greedy push was right in 71% of the safe cells. Holding each push for ten steps widened the gap tenfold and raised that share to 94%. Holding only the random moves, or shortening the horizon, did much less, so most of the help came from the wider gap.
