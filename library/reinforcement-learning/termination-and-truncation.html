Reinforcement Learning

Q-learning that treats its time limit as terminal learns the values of a different grid

With a target that stops only at Gymnasium's terminated flag, the agent finds the optimal values on the course's grid even when a four-move limit cuts 62% of its episodes.

18 min read2026-11-06

Why this matters

Training loops stop episodes after a fixed number of moves. An agent written against Gymnasium, the environment interface the course adopts here, learns why an episode stopped only from what the environment returns. The TD target already handles the end of the task: a terminal state's future is worth 0, so the target is the reward alone. A time limit is a different ending. The cell the agent stands in keeps its value, so the target still bootstraps from it, which is called partial-episode bootstrapping. Gymnasium's step reports the two endings as two flags, terminated and truncated. Given the five values a step returns, you can write its target, and you can predict from one equation what a loop that confuses the two flags learns instead.

A four-move limit stops the agent in cell 7, next to the goal

Start the agent in cell 13 of the course's grid and have it move right, right, up and up. With no slips it stands in cell 7 after the fourth move, one move below the goal. Now add a rule that stops every episode after four moves. The episode ends in cell 7, and the agent still has to update its estimate for its last move, up from cell 11, which paid −1.

Suppose its estimates are already the optimal action values. Cell 7 is then worth 6.48, because its next move reaches the goal's +10 with probability 0.8. Q-learning's target for the move from cell 11 is -1 + 0.9 \times 6.48 = 4.83. A loop that treats the end of the episode as the end of the task uses −1 instead, as if nothing could be earned from cell 7.

Now start in cell 14 and move right, up, up and up. The fourth move lands in the goal and pays +10. This episode would end even without the rule. The goal is a terminal cell, and a terminal cell's value is 0, so the target is 10 and there is nothing to bootstrap. Both episodes stop on move 4 for different reasons, and the right target differs between them.

The course has met the first kind of ending before. Monte Carlo control stopped every episode after CAP = 200 moves. td_control.py kept the cap and already bootstrapped on the capped move, because it reads the next cell's estimate on every move. It recognized the goal and the pit through TERMINAL in gridworld.py. An agent that receives its episodes through Gymnasium does not import the grid's rules, so the environment has to say which ending happened. Gymnasium's step says it with two flags.1

A cut episode still bootstraps from its last cell

A cell's value is the average of the returns that follow it. To see what a cut does to that average, split the return at time T, the move on which the limit stops the episode.

The limit removes the rewards of G_T from the episode. It does not change the cell S_T. The slip rule and the rewards depend only on the cell and the move, never on how many moves came before, so an agent in S_T faces the same future at any time. The average of G_T given S_T is therefore v_\pi(S_T), the cell's value. Averaging the split return gives the value of a cell in terms of a cut episode, as Pardo, Tavakoli, Levdik and Kormushev wrote it.2

For the move just before the cut, T = t + 1, the equation reads v_\pi(s) = \mathbb{E}_\pi[R_{t+1} + \gamma\, v_\pi(S_{t+1}) \mid S_t = s]. That is the average of the ordinary one-step target, so a time limit changes nothing in it. A terminal cell does change it. No rewards follow a terminal state, so its value is always 0.3 The same argument holds for action values. Written with Gymnasium's flags, Q-learning's target is the following.

The argument needed the limit to sit outside the task. If the task were to earn as much as possible in four moves, cell 12 with one move left would have a different future from cell 12 with four, so the cell alone would not fix the value. The remaining time would belong in the observation, and reaching the limit would be a termination.24 On this grid the task ends only at the goal or the pit, so a time limit is a rule of the training loop.

The two endings can also arrive together. The episode from cell 14 reaches the goal on the limit's last move, so both flags are true. The target above tests terminated alone and gives 10. A target that bootstrapped whenever truncated was true would add the goal's estimate. That estimate keeps its starting value, 0 in the course's tables, because no move starts in the goal.

Gymnasium's step reports the two endings as two flags

Gymnasium defines an environment as a Python class with two spaces and two methods.1 Its current release is 1.4.0, from 5 October 2026, and the listings pin it.5 The observation_space and action_space say what the environment returns and accepts. Discrete(16) is the set of integers 0 to 15,6 so the cells are the observations, and Discrete(4) holds the four moves.

reset starts an episode and returns an observation and info, a dictionary for anything else. A custom environment's reset first calls super().reset(seed=seed), which seeds the environment's generator, self.np_random. A seed passed to the first reset makes a run repeatable, and later resets without one continue the same generator.1

step takes a move and returns five values: the observation, the reward, terminated, truncated and info. Terminated says the agent reached a terminal state of the task. Truncated says that a condition outside the task, typically a time limit, ended the episode. After either one, the loop has to call reset before it steps again.1

grid_env.py puts the grid behind this interface. Its step hands the environment's own generator to step from mc_control.py, which already plays the slip rule. It returns terminated when the agent lands on the goal or the pit. It never returns truncated, because the grid has no limit of its own.

The limit comes from a wrapper, an environment that holds another and changes what passes through it. TimeLimit(env, max_episode_steps=4) counts the moves since the last reset and sets truncated on the move where the count reaches 4. It never changes terminated.7

The demo at the bottom of grid_env.py plays the two episodes of Fig. 1 under that wrapper, with a seed under which none of their moves slips.

In OpenAI Gym before version 0.26, step returned a single flag, done, in place of the two, and marked a time limit only with an entry in info.1

Treated as terminal, the cut makes Q-learning solve a grid that ends at random

q_gym.py is the Q-learning of td_control.py, rewritten to see only what the environment returns. It makes its ε-greedy moves with choose and uses the step size of td0, N(s, a)^{-0.7}, where N(s, a) counts the pair's updates. With cut_is_terminal left False, its target is the one derived above. Setting it True also stops the target at truncated, which is the mistake. Nothing else differs between the two.

Where do the estimates rest under the mistake? The last lesson answered that question for Q-learning by averaging its target over one move from a pair (s, a). With the cut treated as terminal, the target is R(s') on moves that end at the limit and R(s') + \gamma \max_{a'} Q(s', a') on the others. Let p(s, a) be the share of the pair's updates that come on a limit's last move. The slip rule does not look at the clock, so the landing cell s' has the same distribution on those moves as on the rest. Averaging gives the condition for the estimates to rest.

With p = 0 this is the Bellman optimality equation, whose only solution is q_*. With p > 0 it is the Bellman optimality equation of a different grid, on which a move from (s, a) also ends the episode with probability p(s, a), with nothing more to earn. Its right side still shrinks the gap between two sets of estimates by a factor of at most \gamma, so it too has one solution. Each p(s, a) comes from the limit, the starting cells and the way the agent moves, and none of those belongs to the task. Pardo and colleagues call treating such cuts as terminations a common mistake.2

The runs settle where each target's average puts them

limits.py runs both versions with ε = 0.5 for 100,000 episodes, as the last lesson's runs did, five runs per version, under limits from 2 to 200 moves. It grades the estimates against q_*, measures p(s, a) in the second half of each run, and solves the resting-point equation for that p by iteration. uv run limits.py needs gridworld.py, control.py, estimators.py, mc_control.py, td_control.py, grid_env.py and q_gym.py in one folder. It takes about three minutes on the machine used here.

limits.py, complete
The output of uv run limits.py

Under the four-move limit, 62% of episodes are cut, and no episode from cell 12 can reach the goal, which is six moves away. The bootstrapping target still ends 0.12 from q_* on average over the 56 pairs, close to the 0.09 it reaches under a 200-move limit, which cuts nothing. Its largest gaps, at cells 5 and 10 beside the pit, shrink in longer runs. At cell 12 its estimate is −1.69, against an optimal value of −1.73 that counts the goal's +10. Bootstrapping carries that reward back one move per update, through episodes that never contain it.

On average a fifth of each pair's updates come on a limit's last move, and the target that stops there ends 1.15 from q_*. It ends 0.08 from its own resting point, so the derivation predicts what it learns at least as closely as q_* predicts the bootstrapping target. Its estimates are lower than the optimal values in every cell. Cells 2 and 7, next to the goal, change least, because most of their value arrives with the move into the goal, whose target never bootstraps.

Fig. 3 repeats the comparison at every limit. A longer limit cuts fewer episodes, so p shrinks and the mistaken resting point moves toward q_*. At 10 moves, 24% of episodes are cut and the mistake's error is 0.38. With 4% cut at 20 moves, the two targets can't be told apart. The course's cap of 200 moves cut no episode in any run, and the two versions learned identical estimates. That is why the cap did not matter in the last lesson's runs, and why the main runs here use a limit of four moves.

Problems

1. An agent whose estimates equal q_* aims up from cell 11 and receives (7, -1.0, False, True, {}). Later it aims up from cell 7 and receives (3, 10.0, True, True, {}). Write both targets. Which would change under a five-move limit?

Answer

The first target is -1 + 0.9 \times 6.48 = 4.83, since terminated is False. The second is 10, since terminated is True. Neither changes under a five-move limit. The first step would come back with truncated False, which leaves its target as it was, because truncated never enters the target.

2. Monte Carlo control left out the rewards after each cut. Using Pardo et al.'s Eq. (5) above, change a cut episode's returns so that Monte Carlo prediction can use them without that error. What does the change cost?

Answer

Add \gamma^{T-t} V(S_T) to the return from each time t, where S_T is the cell the episode was cut in. An episode that ends at the goal or the pit keeps its returns, since a terminal cell's value is 0. The corrected returns contain an estimate, so they inherit its error. That is the cost TD paid for its quieter targets.

The takeaway

Terminated and truncated, the two flags of Gymnasium's step, call for different targets. Terminated means the task is over and the next cell's future is worth 0, so the target is the reward alone. Truncated means a time limit outside the task cut the episode, and the cell keeps its value, so the target still bootstraps. The target is R + \gamma (1 - \text{terminated}) \max_a Q(S', a), with truncated nowhere in it. Under a four-move limit on the grid, that target finds q_* although most episodes are cut. Stopping it at the limit as well makes Q-learning learn the optimal values of a grid that ends at random, 1.15 from q_* on average.
