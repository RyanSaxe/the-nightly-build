Reinforcement Learning

Cell 5's best move points away from the goal when one move is left

On the slippery grid's four-move task, Q-learning earns the optimal return only when its observation includes the moves left.

15 min read2026-11-28

Why this matters

Some tasks come with their own time limit: earn as much as possible in four moves, or travel as far as possible in 300 steps. A state with the Markov property carries every part of the past that changes the future. When the limit belongs to the task, whether the next move ends the episode depends on the moves already made, so the moves left go in the state beside the cell. Once none are left, nothing follows, and the last move is a termination. An agent that sees the time left is called time-aware. On the slippery grid you will find a cell whose best move changes as the moves run out, and build the environment that lets Q-learning learn both of its moves.

Up from cell 5 is worth −2.9 with one move left and −0.86 with three

Give the slippery grid one new rule. The agent has four moves, and its task is to earn as much as it can with them. After the fourth move the episode is over, wherever the agent stands. Rewards keep the discount of the earlier lessons, \gamma = 0.9.

Cell 5 is three moves from the goal, by way of cells 1 and 2. The pit is next to it, on the right. Put the agent there with one move left. No move can reach the goal now, so the agent can only keep its loss small. Up arrives in cell 1 with probability 0.8 or slips left to cell 4 with probability 0.1, each for −1. With the remaining 0.1 it slips right into the pit, for −20. Its expected reward is 0.8(-1) + 0.1(-1) + 0.1(-20) = -2.9. Left can slip only up or down, so it pays −1 wherever it lands. With one move left, the best move is left, away from the goal.

With three moves left the comparison reverses. Up, right and right can reach the goal on the last move. Backward induction, the method of the next section, puts up at −0.86 and left at −2.26.

The cell alone fixes neither the best move nor the value of a move. A Q-table with one row per cell has one entry for up in cell 5, where the task has four values, one for each number of moves left.

Values with k moves left come from the values with k − 1

Write q_k(s, a) for the value of move a in cell s with k moves left, and v_k(s) for the best of them. A move with k moves left pays its reward and leaves the agent in some cell s' with k - 1. So the move is worth its reward plus the discounted best value from s' with one move fewer, averaged over where the move lands. With no moves left nothing more can be earned, which starts the recursion at zero.

Computing v_1 from v_0, then v_2 from v_1, and on to v_4 is called backward induction. It starts at the last move and works back to the first. Each step is one sweep of value iteration, started from every value at 0. Value iteration repeated the sweep until the values stopped changing, and kept only the last one. The four-move task stops after four sweeps and keeps them all. Sweep k holds the values with k moves left. Value iteration's fourth sweep put cell 13 at −3.44, a value still on its way to −0.71. With four moves left, −3.44 is cell 13's value. The goal is five moves away, so four moves can only pay step costs.

Fig. 1 draws each sweep's greedy moves. In cell 5 the best move is left with one or two moves left and up with three or four. Cell 10, below the pit, makes the same change with down in place of left and right in place of up.

The values need two numbers, the cell and the moves left. Sutton and Barto state the Markov property as a demand on the state, which "must include information about all aspects of the past agent–environment interaction that make a difference for the future."1 On the four-move task, the slip rule and the rewards never depend on the moves made. Whether the episode ends after a move does. Up from cell 5 lands in cell 1 with probability 0.8 at any time. With one move left, the agent arrives there with nothing to come, in a terminal state. With three, it arrives with two moves to come. Those are different next states, and the cell alone can't tell which one follows. So the state is the pair (cell, moves left), and the cell alone breaks the property. The cell leaves out part of the state, as the ball's cell left out its speed.

A pair with no moves left is terminal

No move can be made from a pair with no moves left, so its value is v_0 = 0 in every cell, like the goal and the pit. It is a terminal state. So the step that uses the last move returns terminated, and Q-learning's target stops there. Pardo and colleagues' target stops "at all terminations", and the time limit is one of them.2 Gymnasium's tutorial also counts a time limit inherent to the task as a termination.3

This is the target from the lesson on the two flags, read on pairs. There the cell where a limit stopped the agent kept its value, so the target bootstrapped. Here nothing follows the fourth move.

four_moves.py builds the task as FourMoveGrid, a subclass of SlipperyGrid from grid_env.py. It counts the moves left and returns terminated on the last move. With see_time the agent is time-aware: its observation is cell + 16 × moves left, one integer for each pair. The table in q_gym.py then has a row for each pair, with no change to its code. The listings pin Gymnasium 1.4.0, the current release.4

The demo replays the episode from cell 13 in grid_env.py, with the same seed and the same four moves. The first observation, 77, is cell 13 with four moves left. The last step lands in cell 7 with none left, observation 7, and returns terminated True and truncated False. TimeLimit returned the reverse for the same move.

Only the runs that see the moves left earn the optimal return

moves_left.py tests what each observation lets Q-learning learn. It runs the Q-learning of q_gym.py on FourMoveGrid, five runs with see_time False and five with True. Each run uses ε = 0.5 and 100,000 episodes, as the runs under the four-move cut did. Both versions get the same target and the same flags. The script scores each run's greedy moves by their exact expected return over the task, averaged over the 14 start cells.

moves_left.py, complete
The output of uv run moves_left.py

Every run that sees the moves left earns 0.66, the mean of v_4 over the 14 start cells and the most any policy can earn. Its moves at cells 5 and 10 change between two moves left and three, as Fig. 1's do. The runs that see only the cell earn 0.20 to 0.35.

Fig. 2 shows why, at cell 5. Without the moves left, up gets one estimate for its four exact values, as the ball's cell got one entry for both of its speeds. Left gets one estimate too. Neither move is best with every number of moves left, so whichever move a run's table prefers at cell 5 is wrong with some of them. The runs that see the moves left have an estimate for each number of moves left, and those estimates rank up and left as the exact values do. Their estimate of up with three moves left is the farthest from its exact value, and still well above left's. Up's estimates vary between runs, and on other seeds this one also lands above the exact value.

Cells 5 and 10 are the only cells in Fig. 1 where no single move is best with every number of moves left. To find where the shortfall comes from, moves_left.py gives those two cells backward induction's moves and leaves every other cell's move as the table chose it. Every run then earns 0.66, so the whole shortfall comes from the one move each table makes at cells 5 and 10.

Problems

1. The slip rule and the rewards don't depend on the moves left. Use that to update the estimate of move a in cell s for every number of moves left, from one sample that lands in s'. What target does the estimate with k moves left get?

Answer

The move would have landed in s' and paid R(s') with any number of moves left, so it is a sample for every k from 1 to 4. The estimate with k moves left moves toward R(s') + \gamma \max_{a'} Q((s', k - 1), a'), without the second term when s' is the goal or the pit or when k = 1. Harada called this QT-learning. In his game it learned faster than standard Q-learning on (state, time) pairs.5 Pardo and colleagues note that the shortcut is unavailable once the rewards or the slips depend on the time.2

2. Suppose FourMoveGrid returned the last move as truncated, and q_gym.py bootstrapped there, as partial-episode bootstrapping does after a cut. What would the target read on the last move? Why would the runs still learn the same estimates, and what change to the learner would stop them?

Answer

The target would read the largest entry of a row from 0 to 15, the pairs with no moves left. No move starts from those pairs, so no update changes them, and they keep their starting value of 0. The bootstrapped term is then 0, as it is with terminated. A table that started at any other value would add \gamma times that value to every last-move target. So would function approximation, under which those pairs share weights with pairs that are updated.

The takeaway

When a time limit belongs to the task, the moves left are part of the state, since whether the next move ends the episode depends on them. Backward induction gives the four-move task's values, one sweep of value iteration per move. In cell 5, beside the pit, the best move turns from left to up once three moves remain. A pair with no moves left is terminal, so the environment reports the last move as terminated. With the pair in its observation, Q-learning earned the optimal 0.66 in every run. With the cell alone it earned 0.20 to 0.35. All of the shortfall came from its one move at cells 5 and 10, the two cells where no single move is best with every number of moves left.
