Reinforcement Learning

Gymnasium's environment checker passes a grid with a backward slip

Uniformly random moves earn the same −10.90 under the right slip rule and the wrong one, so only a baseline that favours some moves, like the hand-drawn policy, can expose the bug.

19 min read2026-11-07

Why this matters

When a later lesson hands SlipperyGrid to an off-the-shelf agent, the agent will learn a wrong rule as faithfully as a right one, and a poor result will not say which side is at fault. Gymnasium's environment checker, check_env, inspects only the form of what reset and step return. A rule is tested through what it predicts: a fixed policy whose value the course can solve exactly must earn that value, on average, in the environment. A fixed policy used this way is a baseline. This lesson writes two, random moves and the hand-drawn policy, and adds play by hand and a check of ranges. Each check misses some errors, and for random moves you can derive which ones before any episode runs.

One character sends a slip backward in every cell

Put the agent in cell 10 of the slippery grid and have it aim right, as the hand-drawn policy does there. The slip rule moves it to cell 11 with probability 0.8, and otherwise turns the move a quarter turn, up into the pit or down to cell 14, with probability 0.1 each. One line of step in mc_control.py plays the rule. With the moves numbered 0 to 3 clockwise from up, its two turns are (a + 1) % 4 and (a + 3) % 4.

Write (a + 2) % 4 for the second turn, a change of one character, and in every cell that slip sends the agent straight back. From cell 10, the slip that the rule sends into the pit now lands in cell 9 (Fig. 1). bugs.py below calls this copy of SlipperyGrid SlipBack. Its step still returns an integer cell, a float reward and two flags, as Gymnasium's interface requires.

Gymnasium's documentation recommends calling its environment checker, check_env, after constructing an environment.1 It passes SlipperyGrid and SlipBack alike, with the same single warning, so a pass cannot mean that the slips go where the rule says.

check_env compares an environment only with itself

check_env checks form.2 It asserts that both spaces are well formed, which for Discrete(16) means n > 0 and a scalar shape. It asserts that reset returns an observation inside the space and a dictionary, and that the same seed leaves the environment's generator in the same state while a different seed does not. It takes a step and inspects the five values. Then it resets twice with seed 123, takes the same move after each reset, and asserts that the two steps return equal values. Last, it resets, takes up to two steps and resets again, and asserts that no two of those calls return the same mutable object.

The checker has no model of the grid to compare against. A step's output is compared only with a second run of the same environment,2 and both runs share a seed, so a backward slip happens in both and the two agree.

A pass means that no assertion fired. In what step returns, several faults only warn: an observation of the wrong type or outside the space, a flag that is not a bool, a reward of a non-numeric type.3 The other copies in bugs.py show both outcomes. NeverEnds writes == where grid_env.py writes in, so its goal and pit end nothing, and it passes as SlipperyGrid does. ArrayCell wraps its cell in an array and passes with two more warnings. NoSeed forgets super().reset(seed=seed), and an assertion stops it.

The listings run with uv run from one folder that also holds gridworld.py, estimators.py, mc_control.py and grid_env.py, from the lessons in the Background band.

checker.py, complete

The warning every passing copy gets is about render modes, the ways an environment can draw itself. The checker tries them only on an environment built by gymnasium.make from a registered name. That function would also add PassiveEnvChecker, a check of form on only the first reset and the first two steps of an environment's life.4

The rules fix what each baseline should earn

Fix a policy, and the rules give its value in every cell by the linear solve that gridworld.py sets up. Run the same policy in the environment, and the average discounted return of its episodes estimates the mean of those values over the 14 cells reset starts from, since it picks one uniformly. A gap larger than the noise means the environment does not play the rules.

A fixed policy used as such a reference, or as a floor that a trained agent has to beat, is called a baseline. baselines.py defines two, under names later lessons import. random_policy aims uniformly at random and never reads the observation, and hand_drawn plays the hand-drawn policy PI. exact_value solves the rules through transitions, never through the environment, and gives −10.90 for random moves and 1.36 for the hand-drawn policy. Both sides of the comparison share move and R from gridworld.py, so an error in those would appear on both sides and cancel.

The noise is the standard error, the standard deviation of the returns divided by \sqrt{n} for n episodes. behaviour.py runs each baseline for 4,000 episodes on SlipperyGrid and on each copy with a rule error, under a 200-move TimeLimit, and prints z, the gap in standard errors. A gap beyond 3 is flagged. The third policy in the output, up_or_right, which behaviour.py adds with its exact value, belongs to the next section.

behaviour.py, complete

On SlipperyGrid nothing is flagged. On NeverEnds everything is, by 23 standard errors or more, since an agent can collect the goal's and the pit's rewards again and again until the limit cuts the episode. On SlipBack the hand-drawn mean rises to 2.40, 9 standard errors above 1.36, while random moves earn −10.78, within noise of −10.90. A wrong rule can move a value either way, and the test flags both. Nine more seeds gave the same flags.

Uniform aims average the slip rule away

Fig. 2 writes the slip rule as a table: for each aim, the probability of each direction the agent then moves. The rule puts 0.8 on the aim and 0.1 on each quarter turn. SlipBack moves one 0.1 in every row to the direction straight back, and every column still sums to 1.

Random moves aim each way with probability ¼. Write p(k) for the probability that a move turns k quarter turns clockwise. Both tables give every aim the same p(k), which is all the argument assumes. The sum below gives the probability that random moves take the agent from any cell s to any next cell s'.

The slip rule drops out. Rewards depend only on the cell the agent arrives in, so random moves give the same distribution of cells, rewards and returns under both rules, and no number of episodes separates them. The sum also hides any error that relabels the aims, such as a step that swaps the aims up and down, since it adds the four aims in any order.

The cancellation needs all four aims at weight ¼. up_or_right keeps the random choice but aims only up or right, so it adds just two rows of Fig. 2. Its exact value is −4.18, and on SlipBack its mean falls to −5.23, 6.5 standard errors below (Fig. 3). The hand-drawn policy uses a single row in each cell, and every row differs between the two tables.

The hand-drawn policy aims only up or right, and the rule's slips turn a move only a quarter turn. So it never moves down from a cell where it aims up, such as 5, 9 or 13, or left from one where it aims right, such as 10. An error confined to such moves leaves its value at exactly 1.36, and of the two baselines only random moves, which go every way from every cell, can find it.

Play by hand catches SlipBack at its first backward slip

A player at the keyboard knows which way each move aimed and checks where it landed against the grid itself. The player never reads gridworld.py, so play by hand can also show a wrong move or R, which the baselines share with their exact values. In a 2016 talk on deep RL research, John Schulman lists trying a new task by hand beside watching the random policy and checking the scale of observations and rewards.5 Gymnasium's own play function needs the pygame package and an environment that renders itself as images.6 SlipperyGrid renders nothing, so play.py reads one key per line.

The runs below pipe the same six keys into SlipperyGrid and SlipBack with seed 33, chosen because it shows the slip early. At a terminal you would type them.

Both games draw the same numbers, and on the second move the draw lands in the second slip. Under the rule, aiming right from cell 10 drops the agent into the pit. Under SlipBack it lands in cell 9, which no aim to the right can reach from cell 10. One such move proves the bug, where the hand-drawn baseline averaged 4,000 episodes. Play by hand is weakest against an error in how often an allowed move happens, such as a wrong slip probability.

The rules bound every number an agent will receive

SlipperyGrid's observation is one integer from 0 to 15. Stable-Baselines3 2.9.2, the current release of one library of off-the-shelf agents,7 turns it into a one-hot vector of 16 floats before its network reads it.89 Every input is then 0 or 1, so the observation needs a check of its range, not of its scale.

Each step pays −1, +10 or −20, and nothing in Gymnasium's interface declares or checks that scale.10 The rules bound each episode instead. Under a T-move limit, the lowest undiscounted return is T - 1 ordinary moves and then the pit, -T - 19, and the highest is the goal on the first move, +10.

behaviour.py records the ranges in its random episodes. SlipperyGrid and SlipBack stay inside them, so this check is blind to SlipBack too. NeverEnds breaks both bounds, with undiscounted returns from −761 to 129, and the limit cuts all 4,000 of its episodes. An observation outside the space would show in the cells column on any move of any episode, where check_env and PassiveEnvChecker look no further than the second move after a reset.2

Problems

1. A copy of SlipperyGrid sets SLIP = 0.02 by mistake. Which of check_env, the random baseline and the hand-drawn baseline would flag it?

Answer

check_env passes it, since nothing in it compares a move with the rules. The random baseline cannot flag it. The typo changes only p(k), to 0.98, 0.01, 0, 0.01, and the sum over four equal aims removes p(k). The hand-drawn baseline can, because it uses one row of Fig. 2 in each cell and every row changes.

2. NeverEnds returns terminated False on every move, so a 200-move TimeLimit cuts every episode. What would the Q-learning of q_gym.py, which bootstraps at every cut, learn from it?

Answer

Its target treats both flags correctly, so it learns the optimal values of the grid NeverEnds plays, where arriving in the goal or the pit ends nothing. On that grid the best plan from any cell is to reach the goal and stay there, since aiming up from the goal bumps the wall and arrives in the goal again, for another +10. The agent would learn that task well. Only a check against the rules would show that the task is wrong, for example its returns rising past +10, the most an episode on the real grid can pay.

The takeaway

Gymnasium's check_env checks form: well-formed spaces, a valid reset, repeatable seeding and unshared objects. It passes SlipBack, whose second slip turns back, and NeverEnds, which never terminates. A wrong rule shows when a baseline policy's average return misses the value solved from the rules, unless the environment and the solve share the error. Random moves average away any slip rule that treats every aim alike, so in all ten seeds they missed SlipBack, which the hand-drawn policy flagged. The hand-drawn policy is blind to errors in moves it never makes. Play by hand, judged against the grid itself, exposes an impossible move the first time it happens, and the derived ranges catch an episode that never ends.
