Reinforcement Learning

Action values let an agent improve its policy from episodes alone

Monte Carlo control with exploring starts reached the optimal policy in nearly every run on the course's slippery grid, where no convergence theorem yet applies.

18 min read2026-11-03

Why this matters

To improve a policy, an agent compares the moves open to it in each cell. From state values, that comparison weights each cell a move can land in by the chance of landing there, and an agent that learns from episodes never sees those chances. It can learn what each move is worth instead, by averaging the returns that followed the move, as Monte Carlo prediction averaged returns per cell. The average estimates the move's action value.

The greedy step then compares a cell's averages and needs no model. The agent can also improve after every episode without finishing an evaluation, a case of generalized policy iteration called Monte Carlo control with exploring starts. You will run it until it finds the grid's optimal arrows, and see why no theorem yet promises that it will.

Without the slip rule, state values cannot rank the moves at cell 14

Cell 14 is in the bottom row of the slippery grid, one cell left of the bottom-right corner, and the fixed policy aims up there. Policy iteration found that aiming right is better, worth 0.32 against up's −1.08. It priced right by weighting each cell the move can land in by the chance of landing there, as the first panel of Fig. 1 shows.

An agent that learned state values from episodes has the three values in that sum. It does not have 0.8, 0.1 and 0.1, because those come from the slip rule and the agent only sees what happened. Without them it cannot score right, or any other move, from state values.1

It can score a move by trying it. Suppose the agent in cell 14 aims right once and then follows the fixed policy. The table shows one such episode.

The returns come from the backward pass of first-visit Monte Carlo, with one change: each step is labeled by its (cell, move) pair instead of its cell. Cell 14 appears twice, aimed right and then up, so the episode gives a return to each of those moves, −17.29 to right and −19.00 to up.

One return is noisy, and this one ended in the pit. The average of many returns after a pair estimates the pair's action value, the expected return from taking move a in cell s and following \pi afterward.1

Each return after (14, right) is a sample of q_\pi(14, \text{right}), so their average converges to 0.32 without the agent using any probability.

The greedy step over action values reads no probabilities

Every use of P and R now sits inside q_\pi, and an agent can estimate q_\pi by averaging returns. An agent holding estimates of the action values picks the greedy move in a cell by comparing four numbers. In Sutton and Barto's words, with an action-value function "no model is needed to construct the greedy policy".1

The greedy policy is also no worse than \pi. The policy improvement theorem says that if q_\pi(s, \pi'(s)) \ge v_\pi(s) in every cell, then v_{\pi'}(s) \ge v_\pi(s) in every cell. The greedy step meets that condition, and checking it takes only action values.1

The first equality is what greedy means. The inequality holds because the largest of four values is at least the value of any one of them, the policy's own move included. The last equality holds because \pi picks one move per cell, so taking \pi's move and then following \pi is just following \pi.

Exploring starts give every move returns of its own

Averages exist only for moves the agent has tried. A greedy agent takes one move in each cell, so after an episode's first move every pair it visits is the policy's own. The other three moves in each cell get no returns, and their estimates never change.1 In the code below a move with no returns has no estimate yet, and the greedy step skips it, so the policy could never switch to such a move.

This lesson supplies the missing returns with exploring starts: each episode begins from a random (cell, move) pair, and every pair has some chance of being picked.1 Here the pick is uniform over the 56 pairs, and after the first move the agent follows its policy.

Exploring starts needs an environment that can open an episode at any (cell, move) pair, and play below takes the start pair as an argument. Sutton and Barto note that the assumption "cannot be relied upon in general, particularly when learning directly from actual interaction with an environment".1 The usual alternative, a policy that keeps some chance on every move, needs a lesson of its own.

The runs below depend on the assumption. With explore=False, each episode starts in a random cell with the policy's own move, and none of the 20 runs reaches the optimal policy in 10,000 episodes. Every average then belongs to a move the policy already takes, so each greedy step returns the policy it started from.

Monte Carlo ES improves the policy after every episode

Policy iteration evaluated each policy completely before improving it. From samples, a complete evaluation would take infinitely many episodes. Sutton and Barto call the general scheme generalized policy iteration (GPI): evaluation and improvement interact at any granularity, and neither has to finish before the other runs.1 Value iteration was one case of it, with an improvement folded into every sweep.

Monte Carlo ES, short for Monte Carlo with exploring starts, takes the episode as its unit. After each episode it adds the episode's returns to the averages of the pairs it visited, then makes the policy greedy, which can change only the cells the episode visited. The averages are never reset, so a pair's average mixes returns earned under every policy the agent has used.1

mc_control.py is the complete method. It imports the grid from gridworld.py, printed with the exact solve, and first_visit_mc from estimators.py, printed with Monte Carlo prediction. pairs numbers each pair as 4 × cell + move, so first_visit_mc averages returns per pair as it averaged them per cell. greedy is the improvement step, and step, the environment, is the only function that reads the grid's rules.

A greedy policy in mid-training can press the bottom row into the wall, like the stuck policy, and an episode under it never ends. play stops every episode after 200 moves, so a cut episode's returns leave out whatever would have come later. In the main runs, 84 of 2,000,000 episodes were cut.

experiment.py plays 20 runs of 100,000 episodes, one per seed, each starting from the fixed policy with no averages. A run counts as optimal when every arrow is an optimal move, either up or right at cells 9 and 12, where the two tie. After 10,000 episodes half the runs are optimal, and after 100,000, 18 of 20 are. The two still short are wrong at cell 5, beside the pit, where the best move beats the next by only 0.35. Twenty other seeds repeat the half at 10,000 and do better at 100,000.

Run 0 has three arrows wrong after 1,000 episodes, at cells 9, 10 and 13. By 10,000 only cell 10 is wrong. It aims down, whose exact action value is −0.29, against 0.06 for right. By 100,000 every arrow is optimal.

uv run experiment.py needs gridworld.py, control.py from the policy iteration lesson, estimators.py and mc_control.py in one folder. It installs numpy and takes a little over two minutes on the machine used here.

Unfinished evaluation works when the averages carry over

Improving after every episode means each new policy is judged by averages that mix returns from many earlier policies. Fig. 3 compares it with two slower schedules, which make the policy greedy only every 5,600 episodes, about 100 starts per pair. One keeps the averages, as Monte Carlo ES does. The other clears them at each improvement with forget=True, so each policy is evaluated from scratch, as in policy iteration.1

Waiting 5,600 episodes between improvements gains nothing by the end. It delays the first improvement, catches up by 20,000 episodes, and from 50,000 on has no more runs at the optimal policy than improving after every episode. Clearing the averages is what costs. The cleared schedule never has more than 5 runs at the optimal policy, and it ends with 2. Each of its policies is judged on 5,600 episodes, about 100 returns for each move the policy does not take, while the kept schedule improves at the same episodes and keeps every return.

On this grid evaluation never had to finish before the policy changed, but its averages had to keep their returns.

Only the optimal policy can be a resting point

Sutton and Barto give half an argument that Monte Carlo ES ends at the optimal policy.1 Suppose the policy and the averages stopped changing. The averages would then be that policy's action values, and the policy would be greedy with respect to them, so in every cell the following holds.

The last line is the Bellman optimality equation, and only v_* solves it, so \pi is optimal. A suboptimal policy cannot be a resting point.

The other half, that the process must come to rest, has not been proved for this algorithm in general. Sutton and Barto call it "one of the most fundamental open theoretical questions in reinforcement learning".1 Proofs now cover one variant and two classes of problem, each with conditions of its own on step sizes or on long episodes.

  • Tsitsiklis proves convergence for a variant that updates only the pair each episode starts from, with every pair used as a start equally often, on any finite problem with a discount below 1.2
  • Wang, Yuan, Shao and Ross prove it for first-visit updates to every pair, as in mc_control.py, on problems where an optimal policy never revisits a state.3
  • Delattre and Fournier prove it for first-visit Monte Carlo control on any finite problem with a discount below 1/2.4

None of the three covers mc_control.py on this grid. Tsitsiklis's variant updates only the start pair, where mc_control.py updates every pair an episode visits. The grid's discount is 0.9, above 1/2, and its optimal policy can revisit a state: cell 2's only optimal move, right, slips up into the edge with probability 0.1 and leaves the agent in cell 2. Wang and colleagues list weaker conditions than theirs as an open problem,3 and Delattre and Fournier write that "only half the way is done".4 For this grid the question stays open. The runs show what Monte Carlo ES did on the seeds tried, and no theorem says that every run must end at the optimal policy.

Problems

1. Use the weighted sum from policy iteration to price aiming down at cell 14 under the fixed policy, where v_\pi(13) = -2.01, v_\pi(14) = -1.08 and v_\pi(15) = 1.98. Which cells can the move land in, with what probabilities? Compare your answer with Fig. 1.

Answer

Down runs into the bottom wall and stays in cell 14 with probability 0.8. It slips left to cell 13 or right to cell 15 with probability 0.1 each. Every landing pays −1, so q_\pi(14, \text{down}) = -1 + 0.9\,[\,0.8(-1.08) + 0.1(-2.01) + 0.1(1.98)\,] = -1.78, the down triangle in Fig. 1.

2. Suppose every episode started in cell 13 with a random first move, and the agent followed its policy after that. Which cells could ever change their move?

Answer

Only cell 13. The agent reaches every other cell by following its policy, so the only pair with returns there is the policy's own, and the greedy step keeps it. Exploring starts need every pair, in every cell, to have some chance of opening an episode.

The takeaway

An action value is the expected return after a move in a cell, so an agent can estimate it by crediting each return to the (cell, move) pair it followed. The greedy step over action values compares a cell's averages and needs no model, and the policy improvement theorem still applies. Exploring starts supply returns for moves a greedy policy never takes. Improving after every episode reached the optimal policy within 100,000 episodes in nearly every run. Waiting between improvements did not help, and clearing the averages at each one did harm. Only the optimal policy can be a resting point, but no theorem yet says runs on this grid must reach it.
