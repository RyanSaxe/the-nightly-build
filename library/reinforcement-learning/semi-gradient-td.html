Reinforcement Learning

TD(0) no longer converges to the best fit once states share weights

Gradient Monte Carlo finds the closest fit that 10 shared weights allow on a 1000-state walk, and semi-gradient TD, which ignores the weights inside its own target, settles on one with 4.6 times as much value error.

19 min read2026-11-11

Why this matters

A table gives each state its own estimate, and an update changes only the entry for the state the agent just left. On a random walk with 1000 states, the agent visits state 1 about once every 82 episodes, so that entry barely moves.

Function approximation computes every estimate from a short vector of weights, so one update moves many estimates. Learning becomes stochastic gradient descent on squared error, with the Monte Carlo return or the TD(0) target in place of the true value. TD's version is called semi-gradient, because it ignores how its target depends on the weights. You derive both updates from one objective, then solve the 1000-state walk exactly for where each one settles and check the answers against runs.

One move updates a hundred estimates

The random walk in the n-step lesson had 19 states. Sutton and Barto's Example 9.1 stretches it to 1000.1 Every episode starts in state 500, and each move jumps to one of the 100 states on either side, all 200 jumps equally likely. A jump past state 1 ends the episode with reward −1, a jump past state 1000 ends it with +1, and every other move pays 0. There is no discount, so a return is the episode's outcome.

State aggregation lets a rarely visited state, such as state 1, learn from its neighbours' visits. It splits the states into groups and gives each group one number, called a weight, which is the estimate of every state in the group.1 With Sutton and Barto's 10 groups of 100, states 1–100 get 2.4 visits per episode, and each one updates state 1's estimate.

Fig. 1 follows one TD(0) move. Suppose the weight for states 201–300 is −0.47 and the weight for 301–400 is −0.28. The agent jumps from state 250 to state 320 with reward 0, so TD(0)'s target is 0 + (−0.28). With a step size of 0.1, the weight for 201–300 moves a tenth of the way to the target, to −0.451, and so do the estimates of all 100 states from 201 to 300.

In general, the estimate is a function v̂(s, w) of a weight vector w with far fewer components than there are states.1 Most of the theory covers linear functions,1 where each state s has a feature vector x(s) and the estimate is an inner product.

State aggregation is linear, with x(s) equal to 1 in the component of s's group and 0 elsewhere.1 A table is the case of one group per state. For any linear estimate, the gradient with respect to the weights is ∇v̂(s, w) = x(s).1

Monte Carlo's update is a gradient step on the value error

Ten weights can't match 1000 true values, so an objective has to say which states' errors count most. Sutton and Barto weight each state's squared error by a distribution μ and call the sum the mean squared value error, VE.1

The usual μ is the fraction of time steps the agent spends in each state while following the policy. Sutton and Barto call it the on-policy distribution.1 In an episodic task it comes from η(s), the expected number of visits to s per episode.

In Fig. 2, the agent spends 1.37% of its time steps in state 500, where every episode starts. From the states one jump away, μ falls almost linearly to 0.0147% at each end.1

If the agent were told vπ(St) for each state it visits, stochastic gradient descent would step down the gradient of that state's squared error.1

States arrive in proportion to μ, so on average these steps follow VE's gradient. The agent doesn't have vπ(St), but it has the return Gt, whose average from St is vπ(St). Putting Gt in its place leaves the average step unchanged, and the result is gradient Monte Carlo.1

With step sizes that shrink under the usual conditions, gradient Monte Carlo converges to a local minimum of VE. With linear features the only minimum is the best fit the features allow, which we call wMC.1 Setting VE's gradient to zero makes each aggregated weight a μ-weighted average of its group's true values.

Inside states 1–100, μ(100) is more than three times μ(1), so the weight leans toward state 100's higher value. It is −0.830, against a plain average of −0.846.1

TD's target depends on the weights it updates

TD(0)'s target, Rt+1 + γv̂(St+1, w), reads the weights. The step from equation 9.4 to 9.5 assumed a target that doesn't depend on w.1 Differentiating the squared TD error with the target included gives two terms.

Semi-gradient TD(0) keeps the first term and drops the second. Such methods "take into account the effect of changing the weight vector wt on the estimate, but ignore its effect on the target," and Sutton and Barto say that they are not instances of true gradient descent.1

In Fig. 1's move, δ = 0.19. The full gradient would also lower the weight for 301–400 by 0.019, pulling the target toward the estimate. Semi-gradient TD only raises the weight for 201–300.

walk1000.py holds the walk and both updates. Each update changes one weight, because an aggregated estimate's gradient is 1 in one component. semi_gradient_td reads a finished episode move by move, which matches running it during the episode because the walk ignores the weights.

Linear TD settles where every group's TD error averages zero

With linear features, the average semi-gradient step has a closed form.1

Where b − Aw = 0, the weights stop moving on average. Sutton and Barto call that point the TD fixed point, wTD = A−1b, and linear semi-gradient TD(0) converges to it.1 Tsitsiklis and Van Roy proved the convergence, and bounded the error, for discounted tasks that never end.2 For tasks that end, like the walk, they point to Bertsekas and Tsitsiklis's 1996 book.2

Written as sums over states, b − Aw = 0 and the condition for the best fit differ only in the error inside.

With state aggregation, x(s) picks out a group. Monte Carlo's weights make the μ-weighted value error average zero in every group, and TD's make the μ-weighted TD error average zero in every group. A TD error compares an estimate with the reward and the estimate one move later, never with vπ. So a staircase can balance its own TD errors and still sit away from the true values.

exact.py solves for vπ, η and both sets of weights.

TD's staircase is flatter. Its outer weights sit at −0.693 and +0.731, inside Monte Carlo's ±0.830, and its VE is 4.61 times Monte Carlo's, 0.01363 against 0.00296.

For discounted tasks that never end, Sutton and Barto bound how far the TD fixed point can be from the best fit, crediting Tsitsiklis and Van Roy's analysis.1

With γ = 0.9, the bound allows 10 times the smallest VE. The walk has no discount and it ends, so 1/(1 − γ) has no finite value here. For episodic tasks, Sutton and Barto point to a different bound in Bertsekas and Tsitsiklis's book.1 They weigh TD's larger error against the lower variance of its targets, which often lets TD learn faster.1

The guarantees assume that states are updated in proportion to the on-policy distribution. Under other distributions, bootstrapping methods can diverge, which a later lesson takes up.1

The TD fixed point gets the start state's value exactly

In exact.py's output, TD's weight for 401–500 is −0.0009, close enough to 0 to pass for rounding. It is vπ(500), the start state's value. Adding TD's condition over all ten groups removes the features, since each state is in exactly one group. Multiplied by the expected episode length, the sum that remains is the expected total of one episode's TD errors. With no discount and fixed weights, those TD errors add up to G0 − v̂(S0, w).

So the TD fixed point gets the start state's value exactly, under any grouping. On the walk, the start-state condition holds TD's weight for 401–500 at about 0, where Monte Carlo's is −0.087. In Sutton and Barto's Figure 9.2, too, TD's steps for 401–500 and 501–600 straddle zero unevenly.1 With --start 250, TD's weight for 201–300 becomes vπ(250), −0.4727, and its other weights shift down.

Runs of both methods end on their own exact staircases

runs.py trains both methods on the same 100,000 episodes with constant step sizes. Monte Carlo uses 2 × 10−5, from Sutton and Barto's Figure 9.1,1 and TD uses 2 × 10−4, from a commented-out run in Sutton's code for Figure 9.2.3 A constant step never stops moving the weights, so a run can only end near its method's exact weights.

Each run ends on its own method's staircase, and runs with five more seeds do too. The TD run's VE is 0.013, and the Monte Carlo run's is 0.003.

runs.py --true-next removes the cause of the difference. TD's target reads vπ(St+1) in place of the staircase's v̂(St+1, w), so it averages to vπ(St) as the return does. The run then ends on Monte Carlo's staircase, with a VE of 0.0030.

Problems

1. States A and B share one weight. Every episode starts in A, moves to B with reward 1, then ends with reward 0, with no discount. Find μ, wMC and wTD, compare their VE, and check the start state.

Answer

vπ(A) = 1 and vπ(B) = 0. Each state is visited once per episode, so μ(A) = μ(B) = ½ and wMC = 0.5. TD's condition is ½(1 + w − w) + ½(0 + 0 − w) = 0, so wTD = 1. VE is 0.25 at wMC and 0.5 at wTD. TD's estimate of A is 1, exactly vπ(A).

2. Give every state its own group. What does semi-gradient TD(0) become, and where do both methods settle?

Answer

Each x(s) has its single 1 in component s, so v̂(s, w) = ws is a table and the update is TD(0). TD's condition then holds state by state, r(s) + Σs′ p(s′ | s) ws′ = ws, the Bellman equation, solved by vπ. Monte Carlo's one-state averages are vπ too, and uv run exact.py --groups 1000 prints VE 0 for both.

The takeaway

When estimates come from weights, learning is stochastic gradient descent on the μ-weighted squared value error, with a sampled target in place of the true value. The return doesn't depend on the weights, so gradient Monte Carlo follows VE's gradient on average and, with linear features, finds the best fit. TD(0)'s target reads the weights, and the semi-gradient update ignores that dependence. Linear TD then settles where each group's μ-weighted TD error averages zero. A TD error checks an estimate against the reward and the next estimate, not against vπ, so that point can sit away from the true values. On the 1000-state walk its VE was 4.6 times the best fit's, though it got the start state's value exactly.
