The genre is an expert developer-tool essay: show a practitioner the one
capability that changes their work, with a small code example that proves it.
Study technical writers who make a tool's value land through a precise example
and honest trade-offs, writing for peers (Simon Willison on his own tools,
Julia Evans on developer tooling, a strong engineering-blog tool teardown). The
register is calm and first-principles; the code carries the argument.

This round's focus: how a good tool piece uses one worked example to prove value
rather than tour features, and how it states adoption cost plainly without
hedging. Show what an example that earns its place looks like, and what an
install-tutorial paragraph that should be cut looks like by contrast.
